**페어프로그래밍** **핵심** **규칙**

- 목표·범위 합의: 당일에 끝낼 수 있는 작은 단위로 결과물을 명확히 정합니다.
- 기술·용어 싱크: 필요한 기반 지식과 도메인/영단어 네이밍을 미리 맞춥니다.
- 디자인 합의: 대상 패키지/클래스의 설계를 함께 검토·확정합니다.
- 막힘 없는 코딩 시작: 준비가 충분하다고 합의되면 진행합니다.
- 장비 규칙: 키보드·마우스는 한 쌍만 사용하고, 비운전자는 자신의 랩탑을 닫습니다.
- 시간 주기: 30분 코딩 + 10분 회고·플래닝을 반복합니다. 흐름이 끊기면 준비 단계로 되돌아갑니다.
- 집중·휴식: 문제 없을 때만 적절히 휴식을 섞고, 항해사는 딴짓 금지입니다.

**금기** **사항과** **주의점**

- 준비 미흡 상태에서 토론·재작성 반복 시 즉시 초기 단계로 회귀합니다.
- 항해사가 학습 목적으로 진행을 자주 중단하지 않습니다; 실수 보완에 집중합니다.
- 항해사가 지시하고 운전자가 타이핑 머신이 되는 상황을 만들지 않습니다.
- 설계·결과 합의 없이 시작하거나 중간에 “나머지는 알아서”로 종료하지 않습니다.
- 이슈 티켓과 페어를 강제로 묶어 책임을 모호하게 하지 않습니다; 책임자는 단일화합니다.

**목적과** **올바른** **사용**

- 주요 가치: 코드 품질 향상, 지식·경험 교환.
- 더 적합한 대안이 있는 영역은 코드리뷰·테스트·정적분석·문서 공유로 대체합니다.
- 조직 강제 문화가 아닌 협업 도구로, 실험하고 적합성을 스스로 평가합니다.
